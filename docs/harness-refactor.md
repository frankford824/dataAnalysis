# 电商对账 Harness 重构执行边界

## 当前状态

`main` 上已有一批未提交的通用分析平台改动。它们已通过 Git stash 对象和仓库外
未跟踪文件归档保护，但工作树保持原样，没有 reset、checkout 或覆盖。

本次新增顶层 `harness/`，把电商对账定义为独立限界上下文。阶段 A 不依赖旧
FastAPI、Superset、PBIX 运行时或旧 React 门户。

截至 2026-07-23，本机真实验证已经完成：

- finance-win 专用只读账号和 `finance-win-ro` SSH 入口；
- 103 个候选文件冻结为内容寻址快照，其中包含 7 份只用于规则转译的语料；
- 95 个有限模板匹配，1 个 PBIX 明确标记为仅迁移规格；
- 3 个历史账期、21 项应到要求、4 个批准规则和 3 项版本化保守业务口径；
- 标准化、订单—平台钱包核对、历史差异比较和候选基线命令已经接入真实 DuckDB；
- normalization v4 已写入 602,623 行；未经审核的 Excel 公式描述被忽略，不会吞掉
  原始钱包金额；
- 有限钱包规则已按执行代码 checksum 批准；未命中或歧义仍保持未分类；
- 平台费用增量批次会共存，稳定复合键跨批次分别去除 17、10、0 条重复事实；
- 2603、2604 微信候选已按控制总额、公式污染、来源角色和业务指纹自动裁决，其他快照
  完整保留；证据不足的候选只记录为学习事项，不要求操作者猜选；
- 无模型模式、OpenAI-compatible/Anthropic 运行时连接、真实状态 API 与 React 页面；
- 独立 Docker 镜像和仅主机回环地址的 Compose 工作台。

这些证据证明输入可冻结、文件可有限识别、内核命令会真实写入账本且工作台可运行；
它们仍不证明账目已正确。默认模式将支付宝/微信作为平台钱包证据，银行流水明确为
“不适用”，不会让同一钱包记录重复充当资金腿。当前仍缺少第二组历史输出，三个账期
均有应到文件缺口、控制差额和大量未解释记录，且未通过认证门禁，
`pnl_cell` 因此保持为空。正式历史差异裁决、黄金基线和封存盲测尚未完成。

## 本轮可信度与能力边界

当前 React 工作台新增“数据可信度”入口，以“逻辑店铺 × 月份”呈现“还差文件”“金额对不上”
“等待确认”“正在整理”和“可以使用”。状态来自真实应到文件、核对差额、证据绑定和必要确认；
当前真实运行仍有缺文件、金额差额和待确认范围。这里的“可以使用”只表示通过产品当前门禁，
不是外部审计意见，也不能替代正式黄金基线和封存盲测。

新产生且具备正式证据绑定的待处理事项，可以追溯到内容寻址快照中的原始文件、ZIP 成员、
Excel 工作表和真实来源行号。服务端只返回目标行附近的有界窗口，React 使用 Univer 以只读方式
呈现 CSV/XLSX；不执行公式、不开放编辑和保存，也不写回 finance-win。旧结果证据不足时只能标记
为“历史推断”或“无法恢复”。

目标计划拒绝把月份目录、纯日期或纯编号识别为店铺。重新发现范围时，过期合同通过
`retired + effective_to` 停用，既有账期、运行、快照和证据仍保留，不把清理当前范围变成删除历史。

运行时模型连接支持 OpenAI-compatible 和 Anthropic 协议。提议模型只生成带真实证据引用的候选；
独立复核模型只挑错，且必须与提议模型不同才算独立。引用守卫、模型共识和人工接受都不能直接写入
金额、账本或正式规则。没有模型、密钥错误、限流、超时或两个模型之一失败时，确定性扫描、冻结、
标准化、核对、可信度中心和人工待处理继续运行。

人员主表、运营链接、商品归属和旧绩效 CSV 已可作为历史参考层导入与核验，但这不等于正式
人员—店铺—商品绩效已经启用。正式绩效仍需商品粒度认证账本、完整有效期归属、版本化绩效政策、
确定性重算和独立验收。

## 保留

- `host-agent/` 的 Windows SSH 只读路径策略、稳定窗口和流式读取能力。
- 现有中文部署、安全和运维文档中仍然真实的基础设施说明。
- 旧代码作为迁移期间的参考，不参与 Harness 正确性认证。

真实客户配置、快照、DuckDB、Parquet、报告和模型日志全部位于仓库外。仓库内示例
只使用占位店铺和占位路径。

## 停止扩展

- 通用数据源/模型/PBIX/AI 的空 CRUD。
- 以 16 列损益或 BI 页面是否显示作为对账完成标准。
- AI 自动写金额或账本、自动处置残差，或未经治理与盲测自动晋升正式规则。
- PBIX 运行时解析、任意低代码表达式和多平台万能解析器。
- 任意规则、任意模型自治，以及把单模型自我复核包装成独立复核。
- 在商品粒度认证账本完成前发布正式人员—店铺—商品绩效。

## 明确未启用

- AI 写金额、账本或“可以使用”结论；
- PBIX 自动转换或自动转为 PBIP；
- 任意规则执行和任意模型 L1/L2 自治；
- 经外部审计确认的黄金基线；
- 正式人员—店铺—商品绩效。

## 删除条件

旧 backend/web 只有在以下条件全部满足后才允许删除或归档：

1. 2602–2604 黄金基线冻结；
2. 2605 封存盲测通过；
3. 新 Harness 报告、收件箱、备份恢复和审计导出可独立运行；
4. 用户完成本机验证并明确批准删除范围。

在此之前，重构通过新增独立包完成，不把“删除旧代码”当作进度。

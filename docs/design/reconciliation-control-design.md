# 对账控制面设计说明

## 产品读法

面向没有技术背景的电商经营负责人和实施人员的内网 B2B 对账产品；可信、克制、清晰，重点是任务路径、证据和状态可读性，不是视觉炫技。

设计旋钮：

- `DESIGN_VARIANCE=4`：保持现有企业软件骨架，只在任务时间线、收件箱和状态层级上形成辨识度。
- `MOTION_INTENSITY=2`：仅使用状态过渡、进度更新和抽屉切换；尊重 `prefers-reduced-motion`。
- `VISUAL_DENSITY=6`：桌面允许列表、证据表和时间线同屏，移动端改为列表到全屏详情。

## 设计 Token

- 页面背景：`#f6f8f8`
- 主表面：`#ffffff`
- 主文字：`#172426`
- 次文字：`#607174`
- 分隔线：`#d9e1e2`
- 品牌强调：`#087f83`
- 强调悬停：`#066b6f`
- 成功：`#20845a`
- 等待：`#a76a11`
- 错误：`#b2443e`
- 圆角：控件 `8px`，局部面板 `12px`
- 阴影：只用于移动抽屉或悬浮决策区，不用于普通内容分组
- 字体：中文系统字体栈；数字使用 `font-variant-numeric: tabular-nums`
- 触控目标：至少 `44px`
- z-index：导航 `20`，遮罩 `30`，抽屉 `40`，通知 `50`

## 组件体系

- 应用壳：左侧主导航、顶部企业与用户区域、移动底栏。
- 状态条：连接器状态、最后心跳、程序只读风险。
- 任务时间线：等待执行器、扫描、读取、确定性处理、等待确认、继续处理、完成、失败。
- 数据来源列表：主机、PBIX、BI 使用痕迹、原始目录；只展示读取范围和真实扫描状态。
- 收件箱：桌面列表/详情双栏，移动列表/全屏详情；证据、建议、影响、合同版本和一次性处置分层。
- LLM 配置：模式、服务商、Base URL、密钥状态、模型和三类任务绑定；密钥永不回显。
- 状态组件：加载骨架、空状态、权限不足、主机离线、事件断流转轮询、保存中、成功和失败。

## 文案与交互规则

- “AI 不参与金额计算；不可用时确定性对账继续运行”始终可见。
- “程序只读；系统权限尚未强制只读”在权限整改前不得隐藏。
- 收件箱确认只处理当前事项，明确“不会自动发布为规则”。
- EventSource 断开后显示最后更新时间并降级轮询，不能继续播放模拟进度。
- 每页只有一个视觉上最强的主动作；不存在后端行为的按钮不渲染。

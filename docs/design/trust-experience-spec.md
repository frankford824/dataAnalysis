# 经营数据可信体验规范

本规范面向没有数据分析背景的公司经营者。它不尝试把对账内核暴露给用户，而是把系统已经完成的检查翻译成三个经营问题：

1. 这个月的数据现在能不能用于经营查看？
2. 哪些店铺需要关注？
3. 系统为什么这样判断，我下一步该做什么？

## 可信状态

普通界面只使用以下五种状态：

| 状态 | 业务含义 | 进入条件 |
| --- | --- | --- |
| 可以使用 | 当前已配置的文件完整，金额核对与待确认门禁已通过 | 最新有效运行可认证、没有缺失必需来源、没有未解释差额 |
| 还差文件 | 当前月份缺少系统要求的原始文件 | 必需来源缺失、失败或仍在等待 |
| 金额对不上 | 已有文件之间存在尚未解释的金额差额 | 最新有效运行存在未处理差额 |
| 等待确认 | 文件和计算已完成，但有业务判断尚未确认 | 不满足认证条件，且不存在缺文件或金额差额 |
| 正在整理 | 本机正在处理这个店铺或月份 | 当前存在运行中的计算任务 |

“可以使用”只表示通过当前已经配置并执行的核验，不等于审计意见，也不等于外部真实世界已经被完全证明。

## 白话解释结构

任何问题都必须按相同结构解释：

- 发生了什么：陈述系统观察到的事实。
- 会影响什么：说明会影响销售、退款、费用、利润或完整性中的哪一项。
- 建议怎么做：只给一个当前最有价值的动作。
- 确认后会怎样：说明确认、补文件或重新计算后的结果变化。

不得在普通界面展示 ETL、血缘、Parquet、Schema、SQL、置信度、规则 JSON 等术语。

## 精准证据

每个疑问必须能够从以下入口回到同一份不可变证据：

`疑问 -> 原始文件 -> 压缩包成员（如有） -> 工作表 -> 原始行 -> 字段 -> 原始值 -> 标准化值 -> 处理版本`

浏览器默认只读取目标行附近的有限窗口，禁止把大型原文件整体加载到浏览器。原始文件保持只读，表格查看器禁止编辑、公式执行和外部链接访问。

## 模型边界

模型可以参与结构识别、字段映射、关联候选、差额解释和规则草案。模型输出必须引用当前可见证据；多模型一致不能替代证据验证。任何金额、账期状态、规则发布和正式绩效结果仍由确定性内核及治理门禁决定。

# 可信度体验 Fidelity Ledger

本记录对比设计参考与 2026-07-27 的真实 Docker 浏览器验收。设计参考只定义信息层级，
不作为功能证据；真实截图全部来自 `http://127.0.0.1:8765` 的当前服务与当前数据。

| 核对项 | 设计意图 | 实际结果 | 结论 |
| --- | --- | --- | --- |
| 首屏判断 | 负责人先看到“能不能信”，而不是批次、规则或技术日志 | 首屏直接显示 65 个平台店铺的真实状态总览，并按 2026-02 至 2026-07 切换 | 一致 |
| 店铺 × 月份 | 用一个矩阵同时判断范围与历史连续性 | 桌面端为 65 个平台店铺 × 6 个期间；表格在工作区内部滚动，页面本身不形成长页面 | 一致 |
| 白话解释 | 每个状态只回答“发生了什么、影响什么、建议怎么做” | 右侧说明栏使用相同三段结构；无文件时明确说“尚未找到可用原始文件”，不显示“缺 0 项” | 一致并修正了真实数据边界 |
| 原始依据 | 从疑问一步进入文件、Sheet、真实行，并保留业务解释 | 全屏只读证据工作台打开真实 XLSX `sheet1` 第 576 行；显示真实店铺、期间和差额说明 | 一致 |
| 表格交互 | 熟悉 Excel 的用户可以查看上下文，但不能误改来源 | Univer 仅加载目标行附近的有界窗口，关闭编辑和保存；无可靠字段映射时只定位行，不虚假高亮列 | 一致，实际边界比概念稿更保守 |
| 移动端 | 普通用户先看状态列表，点选后再看详情 | 390×844 下以状态概览和店铺列表为主，无横向溢出；店铺说明通过点选后的底部详情呈现 | 一致，未照搬概念稿中常驻的大底部抽屉 |
| 触控与键盘 | 常用操作可触达、可聚焦 | 移动导航按 44px 触控高度实现；弹层支持 Escape、关闭按钮自动聚焦，页面提供“跳至正文” | 一致 |
| 视觉克制 | 数字可读、状态明显，不用装饰替代信息 | 黑色中性背景、单一蓝色强调、表格和局部面板为主；没有营销 Hero、照片或假指标 | 一致 |
| 真实状态 | 不能用演示数字或“全绿”制造可信感 | 390 个范围全部完成技术处理；160 个等待来源，230 个有结果但未认证，当前认证结果为 0；页面如实阻断 | 有意偏离概念稿的理想样例 |
| 看板口径 | 未认证数字必须与正式结论明显区分 | 看板显示真实待核对总额，同时明确标注“当前范围待复核”和“不能作为正式经营结果” | 一致 |
| 模型边界 | 模型连接状态可见，但不能制造金额可信度 | 页面显示最近真实调用成功、提议模型和独立挑错模型；文案明确金额始终由确定性代码处理 | 一致 |

## 保留差异

1. 概念稿使用占位店铺和理想“可使用”数量；实际界面只显示当前真实数据。
2. 实际证据工作台不提供“确认正确”按钮，因为本轮尚未把该动作与安全的裁决事务完整接通。
3. 当前规则只可靠定位到行时，界面不会把任意第一列冒充问题字段。
4. Univer 懒加载块约 5.06 MB（gzip 约 1.43 MB），只在打开原始依据时下载；后续可继续拆包，
   但这不影响确定性计算或无模型运行。
5. 当前 0 个店铺月份通过全部认证门禁；因此“认证经营结果”和“认证人员绩效”保持不可用，
   不能用待复核总额、历史工资表或模型说明替代。
